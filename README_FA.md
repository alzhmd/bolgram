# بلگرام — درگاه کارت به کارت با تأیید خودکار

این پروژه fork شدهٔ [SyncPay BD](https://github.com/jahidulislamseo/syncpay-bd) است. همهٔ قابلیت‌های آن (پنل پذیرنده، پنل ادمین، API و وب‌هوک HMAC، اپ اندروید Flutter با صف آفلاین، SDKهای PHP/Node/Python، افزونهٔ WooCommerce و WHMCS) حفظ شده و فقط بخش‌های مخصوص ایران جایگزین شده است.

## چه چیزی برای ایران تغییر کرد
- **پارسر پیامک بانک‌های ایران** (`src/parsers/ir`): قالب واقعی ملت، ملی، تجارت، پاسارگاد، رسالت، پارسیان، بلو، شهر، مهر ایران و خاورمیانه، به‌همراه پارسر عمومی برای بقیهٔ بانک‌ها (سامان، سپه، صادرات، آینده، …). از اعداد فارسی، تاریخ شمسی و ریال/تومان پشتیبانی می‌کند.
- **مبلغ یکتا**: هر فاکتور باز یک مبلغ منحصربه‌فرد می‌گیرد (مبلغ پایه + چند تومان). همین مبلغ پیامک واریز را به همان فاکتور وصل می‌کند. مبالغ فاکتورهای ۲۴ ساعت اخیر دوباره استفاده نمی‌شوند تا واریزهای دیرهنگام یا تکراری به سفارش اشتباه نخورند.
- **امنیت**: پیامک رمز پویا/کد تأیید نه در اپ ارسال می‌شود و نه در سرور ذخیره می‌شود. پیامک برداشت نادیده گرفته می‌شود. واریز از فرستندهٔ ناشناس (مثلاً شمارهٔ موبایل جعلی) خودکار تأیید نمی‌شود. پیامک تکراری هم با شناسهٔ پایدار مسدود می‌شود.
- **صفحهٔ پرداخت فارسی** (`public/checkout.html`): اول از مشتری می‌پرسد با کارت کدام بانک پرداخت می‌کند. اگر کارت هم‌بانک داشته باشید همان را نشان می‌دهد. دکمهٔ کپی، تایمر، تأیید لحظه‌ای (SSE) و بازگشت خودکار به فروشگاه دارد.
- **اعلان بله و تلگرام** برای هر پرداخت تأییدشده.
- **اپ اندروید**: فیلتر فرستنده‌های بانک ایران به‌جای bKash/Nagad.

## راه‌اندازی سریع (سرور لینوکس با Node.js 22)
```bash
git clone <repo> && cd bolgram
npm install && cp .env.example .env   # حتماً JWT_SECRET و ADMIN_EMAIL/ADMIN_PASSWORD را پر کنید
npm run build && npm start             # پورت 4000
```
- پنل: `http://SERVER:4000/dashboard.html`
- در پنل، بخش **Payment Methods**: برای هر کارت یک مورد بسازید (`provider_type` = شناسهٔ بانک مثل `mellat`، `account_number` = شماره کارت، `account_name` = نام صاحب کارت).
- در پنل، بخش **Devices**: یک دستگاه بسازید و کد QR آن را با اپ اندروید (`zinipay_forwarder`) روی گوشی‌ای که پیامک بانک را دریافت می‌کند اسکن کنید.
- ساخت فاکتور از فروشگاه: `POST /api/v1/payment/create` با هدر `x-api-key`. مبلغ به **ریال** است و `amount` پاسخ همان مبلغ یکتای قابل پرداخت است. مشتری را به `checkout_url` بفرستید.

## امنیت (مهم)
در نسخهٔ اصلی SyncPay ورود به پنل فقط در مرورگر و با حساب‌های نمایشی بود. API ادمین هم کاملاً باز بود و پنل پذیرنده به هدر `x-merchant-id` اعتماد می‌کرد. همهٔ این‌ها اصلاح شد و حالا ورود و دسترسی فقط سمت سرور با JWT یا API Key انجام می‌شود. وب‌هوک‌ها با کلید اختصاصی هر پذیرنده امضا می‌شوند. هدر `X-Bolgram-Signature: t=<unix>,v1=<hmac>` روی `${t}.${body}` محاسبه می‌شود؛ اگر اختلاف زمان بیشتر از ۵ دقیقه بود، درخواست را رد کنید.

## ساخت اپ اندروید
Flutter 3.x و Android SDK لازم است: `cd zinipay_forwarder && flutter build apk --release`. برای بازار و مایکت همین APK کافی است. Google Play برای مجوز SMS فرم «Permissions Declaration» می‌خواهد.

## تست
`npm test`: ۴۲ تست، شامل سناریوی کامل (مبلغ یکتا ← پیامک ملت ← پرداخت‌شده، جلوگیری از تکرار، رد OTP/برداشت/فرستندهٔ جعلی).
